# avrhvpp

ATmega32U2 で動作する、AVR マイコン用の +12V 高電圧パラレルプログラマ（HVPP）です。
通常は STK500 互換の ISP プログラマとして動作し、専用コマンドを送ると高電圧パラレルプログラミングモード（AVRHVPP モード）に切り替わります。

ヒューズ設定の誤りで ISP が使えなくなったチップ（SPIEN 無効、DWEN 有効など）の読み出しと復旧を主な目的としています。

現在ホストツールから、シグネチャ、ヒューズ、ロックビット、ATmega8／ATmega328PのFlashページ／Intel HEXの読み書き、low/high/extended fuseとロックビットの書き込み、チップ消去ができます。HVPPでATmega328PとATmega8を切り替えたread/writeは、ユーザーによる実機確認済みです。AVRISPの追加機能は模擬テストで確認しており、実機は未確認です。EEPROM読み書きは未実装です。

## 対応ターゲット

Flashのページ／Intel HEX操作は`--target <name>`で次のターゲットを指定します。

| ターゲット | シグネチャ | Flash容量 | ページサイズ | ページ数 |
|---|---|---|---|---|
| `atmega8` | `1E 93 07` | 8 KiB | 64バイト | 128 |
| `atmega48` | `1E 92 05` | 4 KiB | 64バイト | 64 |
| `atmega88` | `1E 93 0A` | 8 KiB | 64バイト | 128 |
| `atmega168` | `1E 94 06` | 16 KiB | 128バイト | 128 |
| `atmega328p` | `1E 95 0F` | 32 KiB | 128バイト | 256 |

ターゲット固有値とワードアドレス計算は`common/target.h`に集約しています。ATmega8は[データシート](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-2486-8-bit-AVR-microcontroller-ATmega8_L_datasheet.pdf)のParallel Programming（218～225ページ）でピン配置、モード移行、アドレス指定、ページロード／書き込み手順を確認しました。

ATmega48／88／168は[データシート](https://ww1.microchip.com/downloads/en/DeviceDoc/Atmel-2545-8-bit-AVR-Microcontroller-ATmega48-88-168_Datasheet.pdf)の32.2～32.7節で拡張ヒューズ、シグネチャ、ページ構成、HVPPピン配置、モード移行、Flashのアドレス指定とページロード／書き込みを確認し、定義を追加しました。3種類とも`--query`で拡張ヒューズを表示します。P／PA／PBなど異なるシグネチャの品種は今回追加していません。新しい3種類の実機確認は未実施です。データシートのモード移行手順はVCCの切り替えを含むため、常時給電の現回路での移行可否も実機確認が必要です。ファームウェアのモード移行処理は変更していません。

未知の名前と複数回のターゲット指定は接続前に拒否します。Flash操作では指定が必須です。ヒューズなどの操作での指定必須化、指定ターゲットとのシグネチャ照合、既存HVPP操作への対応機能による実行可否判定は未実装です。

2026-11-05、ユーザーが両ターゲットを切り替えてread/writeを確認しました（個別の操作条件は未記録）。ページ境界、最終ページ、HEX範囲、消去なしの事前検証、異常応答と終了処理は模擬テストで確認しています。ステップ1～7は完了し、確認範囲の詳細と対象外の機能は`PLAN.md`に記録しています。

最終ビルド記録はFlash 9422 / 32768バイト（28.8%）、RAM 676 / 1024バイト（66.0%）です。

## ハードウェア

- MCU: ATmega32U2（16MHz クリスタル、USB CDC で接続）
- ターゲット: 28 ピン ZIF ソケット（ATmega328P／ATmega8で読み書き確認済み）
- +12V: MT3608 昇圧モジュール（J4 経由）→ 12V レギュレータ（U3）で生成し、PC817 フォトカプラでターゲットの RESET に印加します。印加しないときは R6 により RESET が GND に落ちるので、ソケットのチップはリセット状態で停止しています。
- ターゲットの VCC は常時供給されます（VCC の切り替え回路はありません）。

### ピン割り当て（ATmega32U2 ↔ ターゲット）

| ATmega32U2 | 信号 | ターゲット（ATmega328P DIP28） |
|---|---|---|
| PD0–PD7 | DATA0–7 | PB0–PB5（14–19 番）、PC0–PC1（23、24 番） |
| PB3 | RDY/BSY | PD1（3 番） |
| PB4 | PAGEL | PD7（13 番） |
| PB5 | XA1 | PD6（12 番） |
| PB6 | XA0 | PD5（11 番） |
| PB7 | XTAL1 | XTAL1（9 番） |
| PC2 | +12V 制御（PC817） | RESET（1 番） |
| PC4 | OE | PD2（4 番） |
| PC5 | WR | PD3（5 番） |
| PC6 | BS1 | PD4（6 番） |
| PC7 | BS2 | PC2（25 番） |

STK500 モードでは PB0（RST）、PB1（SCK）、PB2（MOSI）、PB3（MISO）を ISP 用に使い、6 ピンヘッダ J2 に出しています。PB3 は RDY/BSY と共用です。
J3 をショートすると J2 の RST が ATmega32U2 自身の RESET につながり、外部のプログラマから ATmega32U2 にファームウェアを書き込めます。

## ビルドと書き込み

### ファームウェア

avr-gcc と avrdude が必要です。

```sh
cd firmware-atmega32u2
make            # avrhvpp.hex を生成
make write      # 外部 ISP プログラマ（avrisp, /dev/ttyACM0）で書き込み（ヒューズ hfuse=0xD9, lfuse=0x5E も設定）
make readfuse   # ATmega32U2 のヒューズを読み出し
```

`Makefile` はコンパイル時に `.d` ファイルを生成し、ヘッダの依存関係を追跡します。

### ホストツール

C++17 のコンパイラが必要です。Qt Creator で `app/avrisp.pro` を開くか、次のようにビルドします。

```sh
cd app
g++ -std=c++17 main.cpp serial.cpp -o avrhvpp
```

リポジトリのルートで`make -C tests`を実行すると、実機不要のプロトコルテストを実行できます。実際のホスト送受信処理とファームウェアのコマンド処理を使い、GPIOとシリアルを模擬します。電気信号やタイミングは実機で確認してください。

## 使い方

### STK500 互換モード（ISP）

電源投入時はこのモードです。ArduinoISP 由来の STK500v1 実装なので、avrdude からは `avrisp` として使えます。

```sh
avrdude -c avrisp -P /dev/ttyACM0 -b 19200 -p atmega328p -U flash:w:foo.hex
```

### AVRHVPP モード（高電圧パラレル）

ホストのプログラマ種別は`-d <device>` / `--device <device>`で指定します。既定の`hvpp`では従来のHVPP操作を使用できます。`avrisp`ではSTK500v1経由のシグネチャ、`--query`（`-q`）、ヒューズ／ロック、Flashページ／HEXの読み出しに対応します。ヒューズ／ロック書き込み、チップ消去、Flashページ書き込みにも対応します。AVRISPの`--write-hex`にも対応します。

```sh
./avrhvpp --port /dev/ttyACM0 --device avrisp --read-signature
./avrhvpp --port /dev/ttyACM0 --device avrisp -q
./avrhvpp --port /dev/ttyACM0 --device avrisp -rfl -rfh -rl
./avrhvpp --port /dev/ttyACM0 --device avrisp --target atmega328p --read-page 255 page.bin
./avrhvpp --port /dev/ttyACM0 --device avrisp --target atmega8 --read-hex flash.hex
./avrhvpp --port /dev/ttyACM0 --device avrisp --target atmega328p --write-hex firmware.hex
./avrhvpp --port /dev/ttyACM0 --device avrisp --target atmega328p --write-hex firmware.hex --no-chip-erase
```

AVRISPの送受信は分割されても全バイトが揃うまで処理し、応答の`STK_INSYNC`と`STK_OK`を検証します。同期は最大3回試し、各応答は1秒の期限で読み取ります。複数の読み出し操作は1回のプログラミングセッションで順に処理し、全読み取りと終了処理が成功してから成功結果を表示します。`--target`を指定した場合は、ターゲット定義から生成した標準のSET_DEVICE／SET_DEVICE_EXT設定をモード移行前に送信します。指定ターゲットとのシグネチャ自動照合は行いません。

`--query`は`--target`不要で、HVPPと同じ形式でチップ情報と対応するヒューズ／ロックを表示します。単独のヒューズ／ロック読み出しでは、指定ターゲット、またはシグネチャから検索した定義を使います。未知のシグネチャでは検索に失敗し、ヒューズ／ロックを読みません。ATmega8の拡張ヒューズは`--query`で省略し、単独の`-rfe`指定は拒否します。ページ／HEX読み出しは`--target`必須です。ページ全体／Flash全体の読み出し成功後にファイルを保存するため、通信途中の失敗では対象ファイルを作成・上書きしません。保存後に終了処理が失敗した場合は、保存済みファイルを残して非0で終了します。

AVRISPの`--write-page`は`--target`必須で、入力サイズとページ番号を接続前に検証します。内容が一致するページは書き込みを省略し、全バイトFFのページだけを書き込み、それ以外は消去せず拒否します。書き込み後はページ全体を読み戻して照合します。`--chip-erase`は完了待ち後にロックビット解除と全FlashのFFを確認します。EEPROMの消去・保持はターゲットのEESAVE設定に従います。

ページ／HEXのファイル処理とページ走査はHVPP／AVRISPで共通です。`--write-hex`は接続前にHEX全体を検証し、既定でチップを消去してから、HEXで指定されたページだけを書き込みます。`--no-chip-erase`では全対象ページが空か一致することを先に確認し、競合や読み出し失敗があれば1ページも書きません。一致ページは省略し、HEXに含まれないページは書き込みません。`--device`、`--target`、`--no-chip-erase`の記述位置によらず、操作は左から順に実行します。

ヒューズ／ロック書き込みと消去では、指定ターゲットがなければ、最初に独立した読み出しセッションでシグネチャから定義を検索します。定義を確定して標準設定を送り直してから、指定操作を順に実行します。未知のシグネチャには書き込み・消去を送りません。ATmega8は書き込み後10 ms／消去後20 ms待機し、他4チップはRDY/BSYのbit 0を最大100 msポーリングします。STK500のACKだけでは成功と判定しません。

予約ビットは1へ正規化し、有効ビットで読み戻しを照合します。SPIENの変更と、消去なしのロックビット0→1変更は拒否します。ATmega8の拡張ヒューズ書き込みも拒否します。失敗後の操作は停止し、非0で終了します。それまでに照合済みの書き込み・消去は失敗時も表示し、取り消しません。失敗した要求は再送しません。単独ページ書き込みで自動消去は行いません。

モード移行を試みた後は、要求の境界を確認できる場合に終了コマンドを送り、終了処理は一度だけ再試行します。2バイトの同期・モード開始・シグネチャ読出し・終了要求は、送信済み位置から残りを補って終了を試みます。可変長要求の途中送信失敗では、残りを埋めたり要求を再送したりせず接続を閉じ、プログラミングモードの解除を確認できないことを報告します。

不明なプログラマ種別、種別の重複指定、AVRISPで未対応の操作は接続前に拒否します。`--device`の位置にかかわらず、全操作の検証が済んでから接続します。

```sh
./avrhvpp -p /dev/ttyACM0 --read-signature      # シグネチャを読み出し
./avrhvpp -p /dev/ttyACM0 --query              # チップを検出し、対応するヒューズとロックビットを表示
./avrhvpp -p /dev/ttyACM0 --read-fuse-low       # low fuse を読み出し
./avrhvpp -p /dev/ttyACM0 --read-fuse-high      # high fuse を読み出し
./avrhvpp -p /dev/ttyACM0 --read-fuse-extended  # extended fuse を読み出し
./avrhvpp -p /dev/ttyACM0 --read-lock           # ロックビットを読み出し
./avrhvpp -p /dev/ttyACM0 --target atmega328p --read-page 0 page.bin # Flashのページ0を128バイトのファイルへ保存
./avrhvpp -p /dev/ttyACM0 --target atmega328p --read-hex flash.hex   # Flash全体をIntel HEXへ保存
./avrhvpp -p /dev/ttyACM0 --target atmega328p --write-page 0 page.bin # 128バイトのファイルをFlashのページ0へ書き込む
./avrhvpp -p /dev/ttyACM0 --target atmega328p --write-hex example/blink.hex # Intel HEXをFlashへ書き込む
./avrhvpp -p /dev/ttyACM0 --target atmega328p --no-chip-erase --write-hex example/blink.hex # チップ消去せずに書き込む
./avrhvpp -p /dev/ttyACM0 --write-fuse-low 0x62 # low fuse に 0x62 を書き込む
./avrhvpp -p /dev/ttyACM0 --write-lock 0xFC     # ロックビットに 0xFC を書き込む
./avrhvpp -p /dev/ttyACM0 --chip-erase          # Flash、EEPROM、ロックビットを消去
./avrhvpp -p /dev/ttyACM0 --dump-buffer         # 共有バッファを16進ダンプする（デバッグ用）
```

ヒューズ値を誤るとISPでアクセスできなくなることがあります。ロックビットは0のビットがプログラムされ、1へ戻すにはチップ消去が必要です。チップ消去はFlashとロックビットに加え、EESAVE fuseがプログラムされていなければEEPROMも消去します。Flashページ書き込みは、ページが消去済み（全バイト `0xFF`）か、すでに入力データと完全一致する場合だけ成功します。`--write-hex` は既定で書き込み前にチップ消去します。消去したくない場合は `--no-chip-erase` を指定してください。書き込む値と対象チップを確認してから実行してください。

シグネチャの出力例:

```
0x1e, 0x95, 0x0f
```

`--query`（省略形`-q`）は`--target`を指定せずに実行できます。シグネチャ3バイトから定義済みターゲットを検索し、チップ名、ページサイズ、総ページ数、Flashサイズと、対応するヒューズ／ロックビットを表示します。ATmega328Pの場合の出力例:

```text
signature: 0x1e, 0x95, 0x0f
chip: ATmega328P
page size: 128 bytes
page count: 256
flash size: 32768 bytes
fuse lo: 0x62
fuse hi: 0xd9
fuse ex: 0xff
lock bits: 0xfc
```

上記のヒューズ／ロック値は例です。ATmega8では拡張ヒューズを読み出さず、その行も表示しません。未定義のシグネチャでは`chip: unknown`を表示し、ヒューズ／ロックを読まず非0で終了します。取得失敗や異常応答でも後続操作を停止します。検出結果は後続のFlash操作の`--target`指定を変更しません。

オプション:

| オプション | 内容 |
|---|---|
| `-p <port>`, `--port <port>` | シリアルポート（Windows では `COM3` など） |
| `-d <device>`, `--device <device>` | プログラマ種別（既定`hvpp`、`avrisp`は読み出しとヒューズ／ロック／ページ／HEX書き込み・消去に対応） |
| `-t <target>`, `--target <target>` | ターゲットを選択（`atmega8`、`atmega48`、`atmega88`、`atmega168`、`atmega328p`）。Flashページ／HEX操作では必須 |
| `-s <speed>`, `--speed <speed>` | ボーレート（既定 115200。USB CDC なので通常は無関係） |
| `--debug` | 予約済みのデバッグコマンドを送る。ファームウェア側の処理は現在無効で、応答しない |
| `-q`, `--query` | シグネチャ、検出したチップ名、対応するヒューズとロックビットを表示する。`--target`不要 |
| `-rs`, `--read-signature` | シグネチャ3バイトを読み出す |
| `-rfl`, `--read-fuse-low` | low fuseを読み出す |
| `-rfh`, `--read-fuse-high` | high fuseを読み出す |
| `-rfe`, `--read-fuse-extended` | extended fuseを読み出す |
| `-rl`, `--read-lock` | ロックビットを読み出す |
| `--read-page <page> <file>` | 選択ターゲットのFlashページをバイナリファイルへ保存する |
| `--read-hex <file>` | 選択ターゲットのFlash全体をIntel HEXへ保存する |
| `--write-page <page> <file>` | 選択ターゲットのページサイズと一致するバイナリファイルを指定ページへ書き込む |
| `--write-hex <file>` | Intel HEXを解析し、チップ消去後に指定されたFlashページを書き込む |
| `--no-chip-erase` | `--write-hex` 前の自動チップ消去を無効にする。引数内の位置は問わない |
| `-wfl`, `--write-fuse-low <value>` | low fuseへ1バイト書き込む |
| `-wfh`, `--write-fuse-high <value>` | high fuseへ1バイト書き込む |
| `-wfe`, `--write-fuse-extended <value>` | extended fuseへ1バイト書き込む |
| `-wl`, `--write-lock <value>` | ロックビットへ1バイト書き込む |
| `--chip-erase` | Flash、EEPROM、ロックビットを消去する。ヒューズは変更しない |
| `--dump-buffer` | 共有バッファを16バイト×16行の16進数で表示する（デバッグ用） |

コマンドの指定は必須です。書き込み値は16進数で、`0x62`または`62`のように00～FFの範囲で指定します。複数の操作を指定した場合は左から順に実行し、失敗した時点で停止します。ポートや通信速度を含む全引数を検証してから接続するため、オプションの記述順に制約はありません。

## 通信プロトコル

### モードの切り替え

| 送信 | 応答 | 動作 |
|---|---|---|
| `.AVRHVPP.` | `AVRHVPP\r\n` | AVRHVPP モードに切り替え |
| `.BITBANG.` | `BITBANG\r\n` | BITBANG モード（ISP ピンの直接操作）に切り替え |
| 0x40 未満のバイト | — | どのモードからでも STK500 モードに戻る |

0x40 未満のバイトで自動的に戻るのは、avrdude などの STK500 クライアントを、モードを意識せずにそのまま使えるようにするためです（STK500 のコマンドは `'0'` = 0x30 などから始まります）。
その代わり、AVRHVPP モードで使えるコマンドやデータは 0x40 以上に限られます。任意の値は複数の0x40以上のバイトへ符号化して送る設計です。

ホストツールは切り替えの前に `'0'` と `' '` を送り、`0x14 0x10`（STK_INSYNC、STK_OK）が返ることを確認して同期を取ります。

### AVRHVPP モードのコマンド

コマンド値は `common/commands.h` でファームウェアとホストツールの間で共有しています。

操作の成功応答は`1\r\n`、読み出しデータは大文字の16進文字列と`\r\n`、エラーは`E<2桁の16進コード>\r\n`です。旧プロトコルとの互換性はありません。ホストとファームウェアを両方更新してください。

| エラー | 内容 |
|---|---|
| `E01` | 引数、設定状態、共有バッファ長が不正 |
| `E02` | プログラミングモードへの移行失敗（メーカーコード不一致） |
| `E03` | RDY/BSYタイムアウト |
| `E04` | 書き込み後の読み戻し検証失敗 |
| `E05` | 書き込み先が消去済みでも入力データと一致してもいない |
| `E06` | 未知のコマンド |

ホストは応答解析を共通化し、エラーや不正な応答を受けた時点で後続操作を中止します。

| コマンド | 応答 | 動作 |
|---|---|---|
| `CMD_CLEAR`（0x40） | なし | 一時データ、Flash操作パラメータ、バッファアドレス、256バイトの共有バッファを初期化する |
| `CMD_DEBUG`（0x4F） | なし | 予約済み。現在は処理が無効 |
| `CMD_READ_SIGNATURE`（0x50） | 16進6文字 + `\r\n` | シグネチャ3バイトを読み出す |
| `CMD_READ_FUSE`（0x51） | 16進2文字 + `\r\n` | 共有バッファの先頭で指定したヒューズを読み出す |
| `CMD_READ_LOCK`（0x52） | 16進2文字 + `\r\n` | ロックビットを読み出す |
| `CMD_READ_PAGE`（0x53） | `1\r\n`またはエラー | 指定した開始ワードアドレスから指定バイト数を共有バッファへ読み出す |
| `CMD_CHIP_ERASE`（0x60） | `1\r\n`またはエラー | チップ消去を実行する |
| `CMD_WRITE_FUSE`（0x61） | `1\r\n`またはエラー | 共有バッファで指定したlow/high/extended fuseへ値を書き込む |
| `CMD_WRITE_LOCK`（0x62） | `1\r\n`またはエラー | 共有バッファで指定した値をロックビットへ書き込む |
| `CMD_WRITE_PAGE`（0x63） | `1\r\n`またはエラー | 指定した開始ワードアドレスへ指定バイト数をページ書き込みする |
| `CMD_ADDR0` / `CMD_ADDR1`（0x70 / 0x71） | なし | 共有バッファの読み書き位置を設定する |
| `CMD_DATA0` / `CMD_DATA1`（0x72 / 0x73） | なし | 共有バッファの現在位置へ1バイト書き込み、位置を1進める |
| `CMD_LATCH_FLASH_PARAMS`（0x7D） | `1\r\n`またはエラー | 共有バッファ先頭の4バイトからFlash操作パラメータを確定し、共有バッファをクリアする |
| `CMD_READ_16BYTES`（0x7F） | 16進32文字 + `\r\n` | 共有バッファの現在位置から16バイト読み出し、位置を16進める |
| `CMD_LOAD_7BITS`（0x80～0xFF） | なし | 下位7ビットを一時データとしてロードする |

ファームウェアのSTK500処理とAVRHVPP処理は、同じ256バイトの `flush_buffer` を共有します。AVRHVPPの操作では、最初に `CMD_CLEAR` でバッファと書き込み位置を初期化します。任意の1バイトは `CMD_LOAD_7BITS` で下位7ビットをロードした後、最上位ビットに応じて `CMD_DATA0` または `CMD_DATA1` を送ることで現在位置へ格納されます。格納後、位置は自動的に1進みます。

`CMD_READ_FUSE` の対象番号は0がlow fuse、1がhigh fuse、2がextended fuseです。ホストツールは対象番号を共有バッファの0番へ格納してから読み出しコマンドを送ります。

ヒューズ書き込みでは共有バッファの0番に対象番号、1番に値を格納してから `CMD_WRITE_FUSE` を送ります。ロックビット書き込みでは0番に値を格納してから `CMD_WRITE_LOCK` を送ります。ファームウェアは先頭から連続して設定されたバイト数とFuse番号の範囲（0～3、3はlock）を検証しますが、チップ別の対応機能は検証しません。

Flash操作では`CMD_CLEAR`後、次の4バイトを先頭から連続して格納し、`CMD_LATCH_FLASH_PARAMS`で確定します。

| バッファ位置 | 値 |
|---|---|
| 0 | 開始ワードアドレスの下位バイト |
| 1 | 開始ワードアドレスの上位バイト |
| 2 | 処理バイト数の下位バイト |
| 3 | 処理バイト数の上位バイト |

処理バイト数は2～256の偶数で、256は`00 01`です。操作範囲は16ビットのワードアドレス内に収めます。ラッチ時に共有バッファと位置が初期化されるため、ホストは成功応答を受けてから読み出しコマンドまたは書き込みデータを送ります。パラメータは1回の読み書きで消費され、`CMD_CLEAR`とモード切り替えでも無効になります。旧ページ番号コマンド0x7Eは`E06`を返します。

ファームウェアは`common/target.h`を使用せず、チップ容量、ページ境界、対応機能、完全なシグネチャを検証しません。ホストは選択ターゲットの定義から開始ワードアドレスとページサイズを送ります。`CMD_READ_PAGE`が成功したら、バッファアドレスを0に設定し、`CMD_READ_16BYTES`をページサイズに応じた回数（64バイトのページは4回、128バイトのページは8回）送って回収します。16バイトが共有バッファ内に収まらない読み出しは`E01`を返します。

`--read-hex` は `CMD_READ_PAGE`で選択ターゲットの全ページを読み出し、すべて成功した後に出力ファイルを作成します。Intel HEXは16バイトのデータレコードとEOFレコードで構成し、全バイト `0xFF` のデータレコードは省略します。省略されたアドレスは消去済みの `0xFF` として扱います。

Flashページ書き込みでは、上記のパラメータをラッチした後、指定サイズのデータを先頭から連続して格納し、`CMD_WRITE_PAGE`を送ります。ファームウェアはパラメータと受信長を検証します。現在の内容が入力と完全一致する場合は成功し、全バイト`0xFF`の場合だけ実際に書き込みます。書き込み後は指定範囲を再読出しし、完全一致した場合だけ成功を返します。

`--write-hex` はIntel HEXのチェックサム、EOF、重複データ、選択ターゲットのFlash範囲を接続前に検証します。データ、EOF、拡張セグメントアドレス、拡張リニアアドレス、開始アドレスの各レコードに対応します。検証成功後、既定ではチップ消去を実行し、HEXで指定されたページを読み出して消去を確認してから `CMD_WRITE_PAGE` で書き込みます。HEXで省略された領域は書き込み対象になりません。

`--no-chip-erase` を指定すると自動チップ消去を省略します。この場合はHEXで指定された全ページを先に読み出し、各ページが消去済みまたは入力イメージと完全一致することを確認してから、必要なページだけを書き込みます。既存内容と競合するページがあれば、1ページも書き込まず終了します。

実装済みのシグネチャ、ヒューズ、ロックビット、Flashページの読み出し／書き込みとチップ消去は、毎回プログラミングモードに入り、処理後に抜けます。成功／エラーの状態応答は`send_result()`でプログラミングモードと+12Vを解除してから送信します。不正な引数や未知コマンドも同じ終了処理を通り、モード切り替えでも解除します。
プログラミングモードに入れたかどうかは、RDY/BSY が High になることと、シグネチャの先頭がメーカーコード 0x1E であることで判定しています。

## 制約と今後の課題

- Flash読み書きは上記5種類のターゲット定義に対応しています。別チップを追加するときは、シグネチャ、Flash容量、ページサイズ、ページ数、HVPPのアドレス指定と書き込み手順をデータシートで確認し、ターゲット定義として追加します。
- ページ番号はホスト内で16ビットとして扱い、通信では開始ワードアドレスと処理バイト数へ変換します。有効なページ番号、ファイルサイズ、HEXの範囲はホストが選択ターゲットの定義に基づいて検証します。
- `CMD_DEBUG`とEEPROMの読み書きは未実装です。
- 0x40未満でSTK500モードへ戻る仕様を維持するため、任意の8ビット値は `CMD_LOAD_7BITS` と `CMD_DATA0` / `CMD_DATA1` などを使って0x40以上のバイトへ符号化します。
- プログラミングモードへは、VCC を常時供給したまま XTAL1 を 6 回トグルし、+12V を印加する方式で入ります。RSTDISBL がプログラムされたチップでは、ターゲットのプログラムが動いたままになり、モードに入れない可能性があります。対応するには VCC の切り替え回路と、より速い +12V のスイッチが必要です。
